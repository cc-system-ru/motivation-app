# Как обновить приложение на Render

Репозиторий: `cc-system-ru`. Render подключён к нему и при каждом пуше в ветку
`main` (или `master` — смотрите, какая стоит в настройках сервиса) пересобирает
приложение автоматически.

---

## Шаг 1. Скачайте архив с новыми файлами

В чате приложен файл `cc-system-update.tar.gz`. Распакуйте его — внутри папка
`build` с файлами:

```
app.py
motivation_engine.py
config.py
db.py
exports.py
requirements.txt
templates/            ← 10 html-файлов, папку нельзя терять
```

---

## Шаг 2. Замените файлы в GitHub

Откройте https://github.com/cc-system-ru

### 2.1 Корневые файлы

Для каждого из файлов — `app.py`, `motivation_engine.py`, `requirements.txt`:

1. Откройте файл в репозитории.
2. Нажмите иконку карандаша **Edit this file** (или значок с тремя точками → Edit).
3. Выделите всё содержимое (`Ctrl+A` / `Cmd+A`) и удалите.
4. Вставьте содержимое одноимённого файла из архива.
5. Внизу нажмите **Commit changes** → **Commit changes**.

Либо проще: **Add file → Upload files**, перетащите файлы, нажмите
**Commit changes**. GitHub заменит файлы с теми же именами.

### 2.2 Новые файлы

Через **Add file → Upload files** добавьте:

- `config.py`
- `db.py`
- `exports.py`

Они новые, конфликтов не будет.

### 2.3 Папка templates — обязательный шаг

Без неё сайт упадёт с ошибкой `TemplateNotFound`.

1. **Add file → Upload files**.
2. Перетащите **всю папку** `templates` из архива (не отдельные файлы —
   именно папку, GitHub сохранит путь `templates/base.html`).
3. **Commit changes**.

Если перетаскивание папки не сработало: **Add file → Create new file**,
в поле имени введите `templates/base.html` — слэш создаст папку. Так добавьте
все 10 файлов: `_macros`, `analytics`, `base`, `employees`, `index`, `login`,
`payroll`, `payslips`, `period`, `settings` (все с расширением `.html`).

---

## Шаг 3. Проверьте, что старый код не мешает

Если в репозитории остались файлы от прежней версии, которых нет в новом
архиве, удалите их — иначе возможны конфликты импортов.

В вашем репозитории видны только три файла, они все перезаписываются.
Ничего удалять не нужно.

---

## Шаг 4. Дождитесь деплоя на Render

1. Откройте https://dashboard.render.com → ваш Web Service.
2. Вкладка **Events** — там появится `Deploy started` → `Deploy live`.
   Обычно 1–3 минуты.
3. Если статус `Deploy failed` — откройте **Logs**, последние строки покажут
   причину. Типичные: не хватает `templates`, опечатка в имени файла.

---

## Шаг 5. Проверьте настройки сервиса (один раз)

**Settings → Build & Deploy:**

| Параметр | Значение |
|---|---|
| Runtime | Python 3 |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn app:app --bind 0.0.0.0:$PORT --workers 2 --timeout 120` |
| Auto-Deploy | Yes |

**Environment:**

| Переменная | Значение |
|---|---|
| `SECRET_KEY` | длинная случайная строка |
| `DATA_DIR` | `/var/data` |

**Disks → Add Disk** (если ещё нет):

| Параметр | Значение |
|---|---|
| Name | `data` |
| Mount Path | `/var/data` |
| Size | 1 GB |

Без диска база обнулится при следующем перезапуске контейнера — на free-тарифе
это происходит регулярно. Все сотрудники и расчёты пропадут.

⚠️ Если раньше приложение работало без диска и вы уже вводили данные —
они хранятся в эфемерной файловой системе и потеряются при первом же деплое.
После подключения диска база начнётся с чистой: 13 сотрудников из
`db.py` создадутся автоматически при старте.

---

## Шаг 6. Проверка после деплоя

1. Откройте сайт — должен появиться экран входа с паролем.
2. Войдите как `admin`.
3. Проверьте по очереди:
   - **Главная** — инструкция и список из 13 сотрудников;
   - **Сотрудники** → кнопка **Мотивация** у «Иванов Иван» — открывается таблица порогов;
   - **Главная** → **Рассчитать** у «Иванов Иван» → введите 20 выездов, 2 500 км,
     видеоотчёт 1, заднее стекло 1 → **Сохранить расчёт** → итог должен быть **147 000 ₽**;
   - **Расчётные листки** → **Скачать все PDF** — файл на половине A4;
   - **Периоды** → закрыть текущий месяц → **Аналитика** покажет ФОТ и диаграммы.
4. Выйдите и войдите как `KD20` — должны быть видны только сотрудники
   коммерческого департамента, кнопка закрытия периода недоступна.

## Если что-то пошло не так

**`TemplateNotFound: base.html`** — не загрузилась папка `templates`.
Повторите шаг 2.3.

**`ModuleNotFoundError: No module named 'motivation_engine'`** — файл
`motivation_engine.py` не в корне репозитория, а внутри папки. Переместите его
в корень.

**`ModuleNotFoundError: No module named 'reportlab'`** — в `requirements.txt`
не хватает строк. Проверьте, что там четыре строки: Flask, gunicorn, openpyxl,
reportlab.

**Сайт открылся, но пустой список сотрудников** — база создана заново без
сидов. Проверьте, что `DATA_DIR=/var/data` и диск подключён, затем
**Manual Deploy → Clear build cache & deploy**.

**Данные пропали после рестарта** — не подключён диск, см. шаг 5.
